# Web セキュリティベースライン（全プロジェクト共通）

## 役割

すべてのWeb・モバイルアプリで、最低限満たすべきセキュリティ実装を確認・実装する。
個人情報や著作物の有無に関わらず、これらは「やらない選択肢がない」項目である。

---

## ベースライン1：Cookie/セッションの基本

### 必須要件
- 認証Cookieは `HttpOnly` + `Secure` + `SameSite=Strict`
- HTTPS強制（HSTSヘッダー設定）
- セッショントークンをURL・クエリ文字列に含めない
- セッショントークンをログに出力しない

### 確認ポイント
- ログイン処理の `Set-Cookie` ヘッダーに3属性すべて入っているか
- リバプロ/CDN層で属性が剥がされていないか
- 開発環境で `Secure` を外す場合は環境変数で明示分離

---

## ベースライン2：ブルートフォース対策

### 必須要件
- パスワード/トークン認証で N 回失敗したら一定時間ロック・自動失効
- 推奨デフォルト：5回失敗 → 15分ロック、共有トークンの場合は失効
- IPベース + アカウントベース両方のレート制限
- ロック発生時はアカウント所有者へ通知

### 確認ポイント
- 失敗カウンタの保存先（メモリのみだとプロセス再起動で消える）
- 「ロックされました」のレスポンスがアカウント存在の漏洩経路にならないか
- 管理画面・API・共有リンクすべてに適用されているか

---

## ベースライン3：画像アップロード時のEXIF/GPS除去

### 必須要件（画像アップロード機能がある場合）
- アップロードされた画像のEXIFメタデータをサーバ側で除去
- 特にGPS座標は必ず除去（位置情報の意図しない流出防止）
- 除去はクライアント任せにせず、サーバ側で必ず実施

### 確認ポイント
- 元ファイルではなく除去後のファイルが配信されているか
- 動画の場合はGPS情報を含むメタデータ（QuickTime metadata等）の除去
- アップロード→処理→配信のパイプライン全体でEXIFが残らない

---

## このエージェントが扱わないこと
- 個人情報全般の取り扱い（→ pii-handling）
- 著作権・透かし（→ creative-rights）
- 法的判断（→ legal-compliance / legal-advisor-a）

---

## 失敗パターン警告
- 「dev環境では一時的に外す」が本番に持ち込まれる事故
- レート制限を「設定したつもり」でnginxやCDN設定で無効化されている
- EXIF除去をクライアントJSで実施し、悪意あるクライアントから素通り
