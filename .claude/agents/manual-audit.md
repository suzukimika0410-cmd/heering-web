# 手動監査フロー（AIなしのベースライン）

## このドキュメントの位置づけ

AIエージェントは人間の監査の「見落としを補助する存在」である。
人間の監査フローが先に存在し、AIはその補助手段である。

```
正しい関係：
人間が監査する → AIが見落としを補助する

誤った関係：
AIが監査する → 人間が承認する
```

このドキュメントは「AIなしで何をするか」を定義することで、
「AIが何を補助しているか」を明確にする。

---

## A側手動監査フロー

### 新機能追加・設計変更時

**担当：Aの運営チーム**

```
Step 1：法務確認（担当：法務責任者または顧問弁護士）
□ 個人情報の取り扱いに変更はないか
□ 新たな法的リスクはないか
□ 利用規約・プライバシーポリシーの変更が必要か
所要時間目安：1〜3営業日
記録：確認者・確認日・確認内容・判断

Step 2：UX・設計確認（担当：デザイン責任者）
□ ユーザーが安心して使える設計か
□ 個人情報入力フローに問題はないか
□ アクセシビリティ要件を満たしているか
所要時間目安：1〜2営業日
記録：確認者・確認日・指摘事項

Step 3：データ・権限確認（担当：プラットフォーム管理者）
□ データアクセス権限が最小権限の原則を満たしているか
□ KYCフローに問題はないか
□ 取引監視ルールへの影響はないか
所要時間目安：1営業日
記録：確認者・確認日・確認内容

Step 4：財務確認（担当：財務責任者または顧問税理士・会計士）
□ コスト・収益への影響試算は妥当か
□ 資金決済法上の問題はないか
□ 税務上の問題はないか
所要時間目安：1〜2営業日
記録：確認者・確認日・確認内容

Step 5：統合判断（担当：意思決定者A）
□ 上記4ステップの確認記録を受領したか
□ P0指摘事項がすべて対応済みか
□ リリースを承認するか
承認記録：承認者・承認日時・確認した事項・判断理由
```

### 月次定期レビュー

**担当：Aの運営チーム**

```
□ システム健全性の確認（エラーレート・レスポンスタイム等）
□ KPIと異常値の確認
□ 前月からのリスク変化の確認
□ 意思決定者Aへの報告と記録
所要時間目安：半日〜1日
```

## B側手動監査フロー

### 月次定期監査

**担当：意思決定者B・B側専門家（弁護士・税理士・会計士）**

```
Step 1：アクセス準備（担当：意思決定者B）
□ 監査契約の範囲内でデータへのアクセスを準備
□ 仮名化済みデータを取得（独立パイプライン経由）
□ 生データアクセスが必要な場合は人間の監査人を指名

Step 2：実態観測（担当：意思決定者B・監査人）
□ ログの確認（異常パターン・欠損の有無）
□ データフローの確認（設計書との一致）
□ 財務・取引データの確認（レポート値との乖離）
□ ユーザー行動パターンの確認（ダークパターンの有無）
□ CLAUDE.mdの変更履歴の確認

Step 3：専門家評価（担当：B側専門家）
□ B側弁護士：法的実態の評価
□ B側税理士：税務処理の評価
□ B側会計士：財務数値の評価

Step 4：独立レポート作成（担当：意思決定者B）
□ 発見事項の優先度分類
□ A側内部監査との乖離の記録
□ Aへの共有要否の判断

Step 5：記録の保存（担当：第三者管理ストレージ）
□ タイムスタンプ付きで外部ストレージに書き出し
□ 改ざん検知の確認

所要時間目安：2〜3営業日
```

### 無通知監査（不定期）

上記Step 1〜5を予告なく実施。
Aチームへの事前通知なし。

## Claude APIが利用不可になった場合

```
即時対応：
1. 上記手動フローに切り替える
2. 意思決定者AとBに切り替えを通知
3. AI依存していた判断の棚卸しを実施

継続対応：
4. 手動フローで運用を継続
5. AI復旧後も即座に戻さず
   「手動で問題なく動いているか」を確認してから移行
```

---

## 手動フローの限界と記録

```
AIが補助していた内容（手動では時間・コストがかかる）：
・大量ログの異常パターン検知
・複数法令の横断的チェック
・複数エージェントの出力の統合

手動フローで担保できる内容：
・判断の責任主体が人間であること
・記録の真正性
・独立性の実質的な担保
```

このドキュメントを定期的に更新し、
AIシステムが補助している内容を常に把握しておくこと。

---

## 更新ルール

- このファイルはAIエージェントが変更してはならない
- 変更には意思決定者AとBの両方の承認が必要
- 変更履歴をGitで管理する
- 年1回以上の内容見直しを実施する
